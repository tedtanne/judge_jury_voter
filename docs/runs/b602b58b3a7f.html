Cheap tests exist · Needed first: 'Cost estimates start rough, from a handful of runs, and improve as saved runs accumulate'; How it works, bullet 5

A handful of runs cannot cover 25 panels across different content lengths. # Feature request: recommend a panel from the content

## Problem
Judge_Jury_Voter ships 25 preset review panels. A user who passes in content has to know which panel fits. A wrong choice wastes money, and a budget that is too small makes Judges fail: a 9,000-word essay at a $3 limit lost most of its Jury round.

## Proposal
Add a command:

    python -m jjv.cli suggest --url "https://example.com/post"

It accepts the same inputs as review: a file, stdin or --url. It prints what the content looks like, its length, three recommended panels with one sentence of reasoning each, an estimated cost range, and a ready-to-run command with a suggested --max-usd.

Also add `--panel auto`, which picks the top suggestion, prints the choice first, and still respects --max-usd. For MCP clients, add a suggest_panel tool, marked as a small paid call.

## How it works
- One small model call reads the opening and a sample of the rest, expected to cost pennies.
- The model may only pick from the real preset list, so a page cannot invent a panel.
- It should say when no panel fits well, rather than force a match.
- Source files or a diff can pick a code panel with no model call.
- The suggested budget is sized to content length.

## Needed first
- Each preset needs a "use for" description in the code. Today only some have one, and only in the docs.
- Cost estimates start rough, from a handful of runs, and improve as saved runs accumulate.

- The content is untrusted and may try to …
